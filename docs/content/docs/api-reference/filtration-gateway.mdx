The API Gateway is the security and policy control plane. It handles authentication, RBAC, quota enforcement, and policy management. Content safety scanning is handled by the separate [Guardrail Engine](/docs/features/guardrails) on port 8002.

## Base URL
`http://localhost:8000`

## Authentication Endpoints

### `POST /auth/login`
Authenticate user and receive JWT tokens.

**Request:**
```json
{
  "username": "user@example.com",
  "password": "password123",
  "totp_code": "123456"  // Optional, required if 2FA enabled
}
```

**Response:**
```json
{
  "access_token": "eyJ...",
  "refresh_token": "eyJ...",
  "token_type": "bearer",
  "expires_in": 3600,
  "organizations": [
    {"id": "org-123", "name": "My Org", "role": "admin"}
  ]
}
```

### `POST /auth/refresh`
Refresh access token using refresh token.

### `GET /auth/me`
Get current user information.

### `GET /auth/permissions`
Get current user's permissions and allowed models.

### `GET /auth/organizations`
List organizations the user belongs to (paginated).

### `POST /auth/switch-org`
Switch active organization context.

### Invitation Endpoints

| Method | Endpoint | Description |
| --- | --- | --- |
| POST | `/auth/register-invite` | Register a new user via invitation token |
| POST | `/auth/accept-invite` | Accept an org invitation (existing user) |
| GET | `/auth/invitations/{token}` | Get invitation details |

> **Note**: Direct registration (`POST /auth/register`) is disabled. New users must be invited to an organization.

### 2FA Endpoints
- `POST /auth/totp/setup` - Initialize TOTP setup (returns QR code)
- `POST /auth/totp/verify` - Verify and enable TOTP
- `POST /auth/totp/disable` - Disable TOTP

## Proxy Routes (Orchestration)

The API Gateway proxies authenticated requests to the Orchestration Gateway:

| Method | Endpoint | Description |
| --- | --- | --- |
| * | `/api/v1/deployments/{path}` | Deployment operations |
| * | `/api/v1/pools/{path}` | Compute pool operations |
| GET | `/api/v1/logs/{path}` | Deployment log retrieval |
| GET | `/api/v1/provider/resources` | Provider resource discovery |
| * | `/api/v1/inventory/{path}` | Inventory operations |
| * | `/api/v1/deployment/{path}` | Deployment management |
| WS | `/api/v1/deployment/ws` | WebSocket for real-time deployment status |

## Internal Endpoints

These endpoints are for service-to-service communication and require the `X-Internal-API-Key` header.

| Method | Endpoint | Description |
| --- | --- | --- |
| POST | `/internal/context/resolve` | Resolve API key to deployment config |
| POST | `/internal/guardrails/scan` | Scan content for safety violations |
| POST | `/internal/prompt/process` | Process prompt (RAG + templates) |
| POST | `/internal/policy/check_quota` | Check user quota |
| POST | `/internal/policy/track_usage` | Track usage statistics |
| POST | `/internal/logs/create` | Create inference log entry |
| GET | `/internal/models` | List available models/deployments |
| GET | `/internal/config/provider` | Get masked provider config |
| GET | `/internal/config/credentials` | Get unmasked credentials (internal only) |
